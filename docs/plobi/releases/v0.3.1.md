## Plobi v0.3.1

[中文](https://github.com/deyu-deng/Plobi/releases/tag/v0.3.1) | [English](https://github.com/deyu-deng/Plobi/releases/download/v0.3.1/Plobi-0.3.1-release-notes.en.md)

上一版：[v0.3.0](https://github.com/deyu-deng/Plobi/releases/tag/v0.3.0)

相对 v0.3.0，这一版换了订阅额度的底座：各家的登录、模型目录与额度查询转由 magpie 维护，Plobi 不再为每家单独写一套接入，只在 magpie 的列表之上做显示适配。另有两处变化可直接感知——笔记右栏从没有变成五块，上一版在数据目录、自更新与中文名称查找上留下的故障一并修掉。下面每一条都写明与上一版的差别。

安装包见本页面下方资产。

### 新增

- **订阅额度体系交由 magpie 维护** — 上一版每家服务各有一条自己写的接入，服务一侧变化就要改客户端。这一版 magpie 随安装包提供并在启动时运行，各家的登录、模型目录与额度统一由它维护；新增一家由 magpie 侧提供，客户端不再为此增加接入代码。
- **卡片清单跟随 magpie 的 provider 名册** — 上一版卡片清单固定在客户端，magpie 侧的增减都要改客户端。这一版清单读 magpie 自己写出的 provider 名册（22 家），是否出卡、卡片名称与登录方式由 Plobi 侧一张映射表决定：上游改名只改该表的一格，已发布的模型 id 与预设保持不变。
- **本机 magpie 配置导入** — 上一版无此入口。设置页与引导页列出本机已有的 magpie 配置，由用户决定是否导入；导入写副本，原工具保持登录。
- **二级 Agent 会话续接** — 上一版每次进入二级 Agent 都是新开一条会话，上一轮说过的内容不保留。这一版沿用其自身会话。
- **按 Agent 指定模型** — 上一版全机共用一档模型。这一版可在 Models 页为单个 Agent 指定模型，选择写进该 Agent 自己的条目。
- **笔记右栏** — 上一版笔记没有右栏。这一版补齐反向链接、出链、标签、属性与书签五块。

### 改进

- **magpie 独立于客户端升级** — 上一版额度适配层与客户端绑在一起，magpie 一侧连发数版时只能等整包。这一版随包一份作为下限，可写位置另存一份并在解析时优先，摘要取自上游发布页的 `SHA256SUMS`；启动失败的版本被记录并跳过，回退到随包版本。
- **插件集随包提供** — magpie 自身不装插件，空数据目录上的 provider 名册为空，登录入口没有名称可点。这一版随包提供插件清单、名册（22 行，登录态字段已剔除）与 21 个插件包，逐个核对 `sha256`。
- **magpie 独立端口与配置目录** — 端口、配置目录与日志同客户端分开，配置写在数据目录下；启动前探测端口，检测到另一实例时接管其进程记录。
- **使用情况上报关闭** — magpie 默认每日向 `usemagpie.ai` 上报一次使用情况，这一版以 `DO_NOT_TRACK=1` 关闭该上报。
- **本机打包也带离线依赖** — 上一版「首次启动不用联网」只对 CI 出的包成立，本机打出的安装包首启仍要去 PyPI 解析依赖。这一版本机打包同样携带离线依赖。
- **打包前备齐工具链** — 上一版网络一抖，构建就白等或反复重下。这一版打包前先把 Git、Node、Python、uv、ffmpeg 与 ripgrep 凑齐，已下载的部分直接复用。
- **打包前剔除构建垃圾** — 上一版 `dist` 的旧哈希、`__pycache__` 与 `.map` 会跟着进包。这一版打包前移除，并新增 `npm run check:payload` 校验包体，超出预算的项逐项列出。

### 修复

- **模型在选择框中无法切换** — 上一版后端有两份 provider 解析器：凭据一侧认得网关那条腿，切换一侧不认得，点它的模型一律报 `Unknown provider`。这一版插件注册表作为第三个来源兜底，两个方向对同一名称给出同一答案。
- **点 `+` 无法发起登录** — 上一版登录走 Plobi 自己的通道，而 magpie 的登录需要一个终端；渲染层未挂载时停在空白页。这一版由终端执行 `magpie plugin login`，浏览器由 magpie 打开；渲染层存活但未挂载时由主进程重载。
- **订阅额度整屏停在加载状态** — 上一版该屏的分支排在 API 密钥一屏的取数之后，后端校验凭据超时时整屏只剩一个转圈。这一版该分支排在其之前，两屏数据互不阻塞。
- **卡片图标退回首字母** — 上一版图标表按旧腿名查，额度腿的 id 换成 magpie 的 provider id 之后，22 张卡里只剩三张带图标。这一版按新 id 补键：12 家取自 simple-icons 的品牌色字形，5 枚官方标志，其余 3 家无公开矢量图者保留首字母。
- **免费池显示为已配置** — 上一版 OpenCode 免费池没有密钥时仍显示可用。免费池归 magpie 之后，这条腿只认付费密钥，无密钥时如实标注凭据缺失。
- **未跑通的两张 Marvis 卡上屏** — 上一版适配表保留 `marvis_cli` 与 `marvis_gui` 两张卡，两者在本机均无法启动。这一版移出卡片清单，配置中对应的腿默认关闭。
- **magpie 旧版本副本残留** — 上一版每更换一次版本就在磁盘留一份旧副本，单份约 74 MB。这一版替换后清除旧版本。
- **magpie 下载物位置** — 上一版下载的文件放在配置目录内，备份或迁移配置时会被一并带走。这一版移出配置目录。
- **升级后 magpie 接管** — 上一版升级客户端后，已有的副本可能被旧版本占位。这一版正确接管已有副本，随包版本更高时不再被旧版本顶住。
- **卸载保留数据目录记录** — 上一版卸载会删掉数据目录的路径记录，重装后回到系统盘默认位置，放在其他分区的数据看起来像丢了。这一版卸载保留该记录。
- **数据目录不可用时启动失败** — 上一版数据目录位于移动硬盘或副盘、该盘没挂载时，会拿一个不存在的路径去建目录，以 `ENOENT` 终止启动。这一版退到下一档可用目录继续启动，并在启动日志中注明落点与原因。
- **自更新重复下载安装包** — 上一版每次更新都从头下载约 400 MB。这一版已下载完成的包直接复用，中途中断的按已有字节续传，收尾核对官方尺寸，尺寸不符的包不交付安装器。
- **全角字符命名的 Agent 查找失败** — 上一版身份查找只对名册一侧做归一化，查询串保持原样，含全角罗马数字等字符的名称无法命中。这一版两侧使用同一套归一化。
- **身份数据来源** — 上一版身份、描述与行级过滤依赖按 Agent 划分的家目录，而该目录已停止使用。这一版统一读取名册中的条目。
