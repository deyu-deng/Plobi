## 二、Blueprint 红线检查（绝对不能接受的）

### 红线 1：任何 Loading 超过 300ms 没有进度提示

**检查结果**：⚠️ 部分合规

- `PreviewRouter.tsx` 在文件读取时显示 `Loader2` 旋转图标（合规）
- `App.tsx` 在配置检查时显示旋转图标 + 文本提示（合规）
- **缺失场景**：
  - SSE 连接建立期间无加载指示（用户点击发送后到首字出现前，空白状态）
  - Agent 卡片状态从 `pending` → `running` 的过渡无动画提示
  - `TaskKanban` 首次加载任务列表时无骨架屏

**验收缺口**：需要为 SSE 首字等待期和任务面板首屏加载补充加载状态。

### 红线 2：任何对话延迟超过 50ms 才开始显示第一个字符

**检查结果**：❌ 无法验证（无测试）

- `useStream.ts` 在 SSE `onmessage` 触发后才调用 `appendToken`，这意味着：
  - 网络往返（TCP + HTTP + 后端 LangGraph 初始化）全部完成后才显示首字
  - 没有"即时反馈"机制（如先显示一个"思考中"的脉冲指示器）
- **无性能基准测试**验证从用户按下回车到首字渲染的实际延迟

**验收缺口**：需要建立性能基准测试，测量并约束 `send_message → first_token_rendered` 的端到端延迟。

### 红线 3：双击 Agent 卡片进入 Focus Mode 有明显卡顿

**检查结果**：⚠️ 需要实测

- `FocusMode.tsx` 使用 `framer-motion` spring 动画（stiffness: 300, damping: 30）
- 动画本身流畅，但**首次进入 Focus Mode 时**：
  - `TaskKanban` 组件需要挂载并渲染全部任务
  - `PreviewRouter` 需要检查最新输出文件
  - 如果任务列表长或文件大，可能导致帧率下降
- **无 FPS 或交互延迟测试**

**验收缺口**：需要添加 Chrome DevTools Performance 测试或 Playwright 交互延迟测试。

### 红线 4：预览区在成品完成前完全空白

**检查结果**：⚠️ 部分合规

- `PreviewRouter` 在文件读取时显示 `Loader2`
- **缺失场景**：
  - 当 Agent 正在生成文件但尚未完成时，预览区显示"选择文件以预览"（等效空白）
  - 没有"正在生成中..."的占位状态或进度指示
  - 不支持流式预览（随着文件内容逐段生成而实时渲染）

**验收缺口**：需要为"文件生成中"状态添加占位 UI，并评估流式预览的可行性。

## 四、代码健康度详细扫描

### 4.1 术语一致性违规

CONTEXT.md 明确定义的术语在代码中未统一使用：

| 被禁止的别名 | 出现位置 | 应替换为 |
|-------------|---------|---------|
| "子 Agent" | `backend/agents/master.py:176,184` (模板中) | "专业 Agent" |
| "子 Agent" | `backend/main.py:252` (注释) | "专业 Agent" |
| "子 Agent" | `backend/agents/graph.py:3,48,79,103,122` | "专业 Agent" |
| "子 Agent" | `backend/agents/base_agent.py:2` (注释) | "专业 Agent" |
| "子 Agent" | `src/i18n/zh.ts:84` | "专业 Agent" |

**影响**：模板中的术语不一致会导致 LLM 输出混入被禁止的别名，污染对话体验。

### 4.2 架构债务

| 问题 | 位置 | 严重程度 |
|------|------|---------|
| 后端无结构化日志 | 全部 `.py` 文件使用 `print()` | 中 — 生产环境无法分级过滤日志 |
| 前端主 chunk 1.54MB | `npm run build` 警告 | 中 — 首次加载慢，需按路由/code-split |
| RAG 使用 hash fallback 作为 embedding | `backend/rag/indexer.py:52-63` | 低 — 无 OpenAI key 时的降级方案，但语义搜索质量差 |
| `void currentSession` 死代码 | `src/layouts/FocusMode.tsx:30` | 低 — Phase 2 遗留的预留注释 |

### 4.3 调试代码残留

- 前端 12 处 `console.error`：均用于错误处理，不算严重，但生产构建应剥离
- 后端多处 `print`：同上，建议统一为 `logging` 模块
