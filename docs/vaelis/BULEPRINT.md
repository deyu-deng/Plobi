## 一、产品定位

以 AI 为核心的**本地桌面智能工作台**（注意：早期蓝图曾用"操作系统"为比喻，已确认为比喻性表述，实际定位为智能工作台 / Agent 控制台）。

用户通过**协调器 Agent（Master Agent）**进行自然语言对话；协调器理解需求、追问澄清、生成 `plan.md`、调度**专业 Agent（Sub-Agent）**并行执行；所有过程在统一界面中**实时可见**。

- 形态：本地优先（Local-first）桌面应用，基于 Tauri + React。
- 价值主张：**不重造轮子**——融合开源 Agent / 工具生态的能力，统一在一个工作台里。

## 二、术语表（强制，含合规性）

| 术语 | 定义 | 禁止别名 |
|------|------|----------|
| 协调器（Master Agent） | 理解需求、追问澄清、生成 plan.md、调度子 Agent 的编排者，本身不直接执行具体任务 | Master、主 Agent、中央控制器 |
| 专业 Agent（Sub-Agent） | 执行具体任务的工作者。预置角色：Researcher、Engineer、Publisher、Musician、Videographer、Scout | 子 Agent、从属 Agent、工具 Agent |
| plan.md | 协调器生成的结构化任务计划，含任务列表/状态/依赖，是专业 Agent 的权威执行依据 | 任务单、计划书、待办列表 |
| 轻量调度（Fast-Track Delegation） | Master 经 LangGraph 路由到单个 Agent，但不生成 plan.md、不展开 Kanban，以对话流微交互反馈替代完整状态流 | 快捷路径、快速通道、简版调度 |
| 渐进式升维（Progressive Escalation） | 默认走轻量路径，允许用户事后通过 UI 动作升格为完整 plan.md 流程；仅算力成本过高时主动确认 | 升级、提升、自动升格 |

**关系模型**：Session ⊃ 1×Master ⊃ 0..n×Sub-Agent；每任务 → 1×plan.md（0..1）；每 plan.md ⊃ 1..n×Task；每 Task → 恰好 1 个 Sub-Agent；轻量调度绕过 plan.md 但仍经 LangGraph。

## 三、架构总览（能力分层）

```
┌─────────────────────────────────────────────────────────┐
│  UI 层 (Tauri + React)  — 群聊 / Agent 面板 / Focus Mode  │
│  协议：AG-UI 事件流（替换 hand-rolled SSE）                │
├─────────────────────────────────────────────────────────┤
│  编排层 (LangGraph)       — Master 调度 + plan.md + 升维   │
├──────────────────────────────┬──────────────────────────┤
│  能力层 A（内部专业 Agent）    │  能力层 B（外部专家 Agent） │
│  Researcher/Engineer/...      │  OpenHands / browser-use   │
│  协议：MCP + bind_tools 工具回路│  协议：A2A 委派（禁 fork） │
├──────────────────────────────┴──────────────────────────┤
│  工具/集成层 (MCP Servers)  — filesystem/fetch/github…    │
├─────────────────────────────────────────────────────────┤
│  记忆层 (mem0 / Letta)  — 替换 KV 注入 system_prompt      │
└─────────────────────────────────────────────────────────┘
```

**交互范式**：默认轻量调度 → 用户可升格为 plan.md 完整流程（渐进式升维）。

## 七、技术约束（不重复造轮子）

本开发书强制以下技术选型，避免重复造轮子：

1. **编排层**：保留 LangGraph（已选，生产级），挂 checkpointer 以支持流式与中断恢复。
2. **前端协议**：用 **AG-UI**（`ag-ui-langgraph`）替换 hand-rolled SSE —— 白捡流式首字、工具过程可视化、断线重连、人在回路、生成式 UI。**直接对应关系：红线 2、4 的达标方案。**
3. **工具调用**：用 **`bind_tools` + LangGraph `ToolNode`** 建立真实工具回路（替换 `base_agent.py` 的假 execute）。
4. **工具/集成**：优先挂**官方 MCP servers**（filesystem/fetch/github）；多 SaaS 按需用 Composio（慎用）。
5. **记忆**：用 **mem0**（轻量、自托管）或 **LangGraph checkpointer** 先止血，替换 KV 注入。
6. **能力融合**：编码/网页等重活，以 **外部专家 Agent（OpenHands / browser-use）经 A2A 委派**，**禁止 fork 大仓**。
7. **测试**：用 **LangChain 假模型 + pytest-asyncio** 实现确定性 e2e，不依赖 API key。

> 详细映射见 `docs/reusable-oss-and-requirements-2026-07-10.md` 与 `docs/codebase-refactor-investigation-2026-07-10.md`。

## 八、验收方法（如何证明"达标"而非"文件存在"）

AUDIT 的核心教训：**代码存在 ≠ 功能可靠**。本开发书要求每条功能以以下任一方式背书后才算交付：

- **端到端测试**：覆盖 `用户发消息 → 首字渲染` 及 `plan.md 生成 → 分配 → 聚合` 闭环（P0）。
- **性能基准**：红线 2 的 `<50ms` 首字延迟须有可重复基准测试。
- **断言验证**：搜索结果质量、标题质量等须有断言，而非"调用即完成"。
- **术语合规扫描**：CI 中扫描禁别名，违规即失败（NF-6）。
