## 问题

Blueprint 红线："任何对话延迟超过 50ms 才开始显示第一个字符"是绝对不能接受的。当前实现中，用户点击发送后，到 SSE 返回第一个 token 前，界面完全空白，用户不知道系统是否在处理。

实测延迟来源：
1. HTTP POST /send_message 往返
2. LangGraph 状态机初始化
3. Master Agent 首次 LLM 调用
4. SSE 连接建立

总延迟通常在 1-5 秒（取决于网络和模型），远超 50ms。

## 目标

在首字到达前，给用户**即时反馈**，将"等待焦虑"转化为"系统正在工作"的感知。

## 验收标准

- [ ] 用户点击发送后，消息列表立即显示一个"协调器思考中..."的脉冲指示器
- [ ] 首字到达后，脉冲指示器被替换为实际内容（无缝切换）
- [ ] 如果 10 秒内无响应，显示超时提示并允许重试
- [ ] 不引入新的状态管理复杂度（复用现有 streamBuffer / isStreaming 标志）

## 设计决策待确认

1. 脉冲指示器样式：是三个跳动点（...）还是旋转图标？
2. 是否显示具体步骤（"正在分析意图..." / "正在制定计划..."）？
3. 超时阈值：10 秒是否合理？
